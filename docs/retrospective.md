# 踩坑复盘（Retrospective）

> 9 个真实 bug 的完整取证记录：现象 → 定位 → 根因 → 修复 → 预防。每个都是"你遇到最难的 bug 是什么"的现成答案。

## 坑 1：启动器在用户机器上闪退，我的环境却一切正常

**现象**：用户双击 `启动学习助手.bat`，报错后窗口立即关闭；同一段代码在我的测试环境完整跑通两次（HTTP 200）。

**定位**：对比两个环境唯一差异——我的 Git Bash PATH 里没有 System32，`chcp` 命令**执行失败**，批处理从头到尾用默认代码页解析（侥幸成功）；用户环境 chcp 成功执行，触发真正的问题。

**根因**：cmd 按当前代码页逐块读取批处理文件字节，**执行中途切换代码页（chcp 65001）会让解析器的字节位置错位**——后续 UTF-8 多字节的中文行被从中间截断读乱，拼出残缺命令 → 语法中止 → 窗口关闭。

**修复**：bat 改为 GBK 编码（中文 Windows 控制台原生编码）+ 删除 chcp 与 emoji，从根上消除代码页切换。详见 [ADR-004](./adr.md#adr-004启动器批处理使用-gbk-编码v22)。

**预防**：测试环境与目标环境的差异本身就是变量；"恰好失败"的依赖（chcp 没找到）掩盖了"必然失败"的路径。此事已写入 AGENTS.md 红线：**bat 文件必须保持 GBK**。

## 坑 2：仪表盘进度条从上线起就永远是 0%

**现象**：首页仪表盘认真做了各阶段进度条，但任何操作后都是 0%。

**定位**：代码考古——仪表盘读取 `localStorage['it-trainer-progress-<userId>']`，全代码库 grep 该前缀的**写入者：零个**。这是一个只有读端没有写端的"完整"功能。

**根因**：功能在两次迭代中接力开发，读端先落地，写端（页面完成标记）从未被实现，而没有任何测试覆盖"进度是否变化"。

**修复**：补全写端——课程章节页浮动「标记已完成」按钮 + `utils/progress.js` 模块（章节判定/读写/阶段计算），事件联动仪表盘即时刷新。

**预防**：UI 有展示无数据的功能，冒烟测试测不出来（页面不报错）；"用户旅程级"断言（完成标记后进度应变化）才是这类 bug 的克星——已列入遗留改进。

## 坑 3：实操检查在 Windows 上 100% 静默失败

**现象**：作业/实验的实操题（检查文件存在、服务状态、端口监听）在 Windows 上永远"验证未通过"，但没有任何报错。

**定位**：读代码即见——`execSync(command, { shell: '/bin/bash' })`，Windows 宿主不存在 `/bin/bash`；文件检查 `fs.accessSync('/home/user/...')` 同理必然失败。所有失败都被 `catch { return false }` 吞掉，呈现为"功能正常但总不通过"。

**根因**：按 Linux 世界硬编码，且错误处理策略（静默降级）把致命环境问题伪装成了业务结果。

**修复**：`utils/bash.js` 统一执行层——Windows 经 `wsl.exe -e bash -c`（execFileSync **参数数组**，绕开 cmd.exe 引号转义），探测 WSL 缺失时返回安装引导而非静默假失败。详见 [ADR-003](./adr.md#adr-003实操检查统一经-wsl-执行v22)。

**预防**：跨平台代码的 catch 块必须区分"检查不通过"与"环境不可用"——后者应该说话。

## 坑 4：双轨认证——一个没人调用却每次都启动的服务

**现象**：项目梳理时发现 Express 认证服务（3456 端口）随每次启动拉起，但前端组件早已全部改走 localStorage，全代码库对 `/api/*` 的调用数为零。更糟的是：它还在把**用户姓名与手机号明文同步到 `docs/public/data/`**，被 VitePress 当静态资源对外发布（局域网任何设备可读）。

**定位**：grep 驱动的死代码审计——搜索消费方（fetch/API 调用）与生产方（写 public 目录的代码），交叉比对。

**修复**：服务退出默认启动路径（保留 `npm run auth` 排查入口）；停止一切 public 同步；删除已发布的 PII 副本；启动流程从双进程减为单进程。

**预防**：每次架构演进后做"消费方审计"（谁在用这个模块？）；隐私数据的流向（而非存储）才是泄露的源头——`data/` 本地无害，复制到 `public/` 即对外。

## 坑 5：冒烟测试判定构建失败，但构建其实成功了

**现象**：自检脚本报 `vitepress build 失败`，手动跑同样的命令却成功。

**定位**：脚本判定条件是 `r.stdout.includes('building')`，而 vitepress 把进度输出（含 "building client + server bundles"）写到 **stderr**，"build complete" 才在 stdout。我的断言盯错了流。

**修复**：判定改为**退出码 + 构建产物存在性**（`dist/index.html`）——不依赖日志内容的脆弱断言。

**预防**：进程级断言优先用退出码与产物，文本匹配只做补充；工具的输出流向（stdout/stderr）是它自己的约定，别猜，验证。

## 坑 6：WAL 模式下直接复制数据库文件 ≠ 备份

**现象**：审查备份脚本时的隐患——SQLite 开了 WAL（write-ahead logging），最近的事务可能还在 `data.db-wal` 里，只复制 `data.db` 主文件会得到**缺最近写入**的快照，且不报任何错。

**修复**：备份流程固定为：打开连接 → `PRAGMA wal_checkpoint(TRUNCATE)`（把 WAL 落盘清空）→ 关闭 → 复制主文件 → 轮转保留 7 份。详见 [ADR-005](./adr.md#adr-005数据库备份先做-wal-检查点v22)。

**预防**：带内部状态的存储引擎（SQLite/数据库/消息队列）永远使用其官方一致性快照机制，"复制文件"只在引擎配合下才成立。

## 坑 7：上线验收只看 HTTP 200，"缩略图式"验证放过了一屏 UI 问题

**现象**：站点上线时验证手段是 curl 状态码（200 + 标题正确），宣布"上线成功"。用户打开页面后发现：右上角认证条**压在导航栏链接上**（图标文字重叠）、首页 hero 是裂图、仪表盘快速链接在子路径下全是 404——三个真问题，验收零命中。

**定位**：逐条核对——认证条是 `position:fixed; z-index:100` 浮层，而 VitePress 导航栏 z-index 只有 30，浮层必然盖住导航右侧链接；hero 的 `image.src` 写了 `/`（把站点根当图片）；快速链接硬编码 `/roadmap/` 绝对路径，未经过 `withBase()` 拼部署子路径。

**根因**：验收标准错位——**HTTP 200 证明"服务器给了东西"，不证明"页面是对的"**。渲染层问题（层级、路径、资源）只有看渲染结果才能发现。深一层：快速链接 404 的根子是"开发环境永远在根路径"掩盖了子路径部署的差异，和坑 1 的"测试环境差异"同构。

**修复**：认证组件迁入 VitePress 官方导航栏插槽（`nav-bar-content-before`，跟随布局流，物理上不可能重叠）；done-fab 层级降到侧栏之下；快速链接统一 `withBase()`；hero 裂图移除；本次验收改为**真实截图走查**（桌面+移动宽度）。

**预防**：上线验收清单必须包含"打开页面用眼睛看"这一步，最低标准是真截图走查关键页面；涉及路径的链接一律 `withBase()`，并在构建产物里 grep 校验。写进 AGENTS.md。

## 坑 8：Git Bash 里 `BASE_PATH=/xx/ npm run build`，产物资源全指向 C:\Program Files\Git

**现象**：本地按线上子路径模式构建验证，`BASE_PATH=/it-infra-trainer/ npm run docs:build` 正常结束，但浏览器打开后整页**无样式裸渲染**——DOM 检查发现所有 CSS/JS 链接都变成了 `file:///C:/Program Files/Git/it-infra-trainer/assets/...`。

**定位**：dist/index.html 里的 href 真的写着 `C:/Program Files/Git/...`——不是浏览器问题，是构建时就写歪了。Git Bash（MSYS2）会对"看起来像路径的命令参数"做隐式转换，`VAR=/xxx command` 这种前缀赋值同样被转换：`/it-infra-trainer/` 被翻译成了 Git 安装目录下的绝对路径。

**根因**：MSYS 路径转换规则作用于以 `/` 开头的参数/赋值，且**转换发生在我看不到的 shell 层**——命令本身不报错，构建"成功"，坏值直接进产物。与坑 1、坑 7 同构：环境差异在静默处注入。

**修复**：构建命令前加 `MSYS_NO_PATHCONV=1`，并在构建后 grep 产物（`/it-infra-trainer/assets/` 引用数 + 严禁出现 `Program Files`）作为双重护栏。

**预防**：Git Bash 下凡是以 `/` 开头的环境变量赋值/参数都要警惕 MSYS 转换；涉及 base 路径的构建，产物 grep 是必做验收。已写进 AGENTS.md。

## 坑 9：桌面端修好的导航栏，移动端汉堡按钮被挤出屏幕

**现象**：认证组件迁入导航栏插槽后桌面端验证通过；375px 宽真截图走查发现页面可横向滚动（scrollWidth 433 > 375），汉堡按钮 right=434——**整个在屏幕外**，移动端用户无法打开菜单。

**定位**：DOM 扫描所有 `getBoundingClientRect().right > 视口` 的元素，锁定导航栏 `.content` 行——我在插槽里加的注册/登录按钮组占了约 120px，VitePress 移动端导航栏本来就没给第三方内容留空间。

**根因**：只在一个断点做视觉验收。桌面端"看起来对了"的布局改动，在另一断点可能直接破坏可用性；CSS 插槽内容不会自动响应式。

**修复**：`@media (max-width: 767px)` 隐藏导航栏内认证区（移动端抽屉菜单里已有同一组件，功能不缺失），复测 scrollWidth 360 ≤ 375、汉堡回屏内。

**预防**：UI 改动的验收矩阵必须覆盖**桌面 + 移动两个断点**，断言不止"没重叠"，还要"无横向溢出 + 关键交互元素在视口内"。已写进 AGENTS.md。

# 产品说明（Product Brief）

> 一句话定位：**给零基础自学者的离线优先 IT 运维培训系统——"读完"不算数，"测过"才算掌握。**

## 目标用户

**主画像：零基础转行者（自学者）**
- 25-35 岁，非科班或转行，在家自学 IT 运维，目标是 3 年内胜任基础设施工程师岗位
- 痛点：学习资料碎片化（视频/文档/题库散落各处）、"学过了"和"学会了"无法区分、付费平台订阅成本高、内网/弱网环境学习中断
- 关键场景：晚上 1-2 小时碎片学习 → 章节阅读 → 章末小测 → 模块测验达标点亮 → 阶段性看学习报告确认自己在变强

**次画像：被安排学习的企业学员**
- 入职培训/转岗培训中被要求完成学习并提交证明的在职人员
- 痛点：学习平台多为"刷时长+自报完成"，证明力弱；主管无法分辨真学与刷课
- 本产品的回应：**证据分级**——测验达标验证与仅自报已读在学习报告中永远分开呈现（ADR-011），刷课刷不出"验证"标记

## Jobs-to-be-Done

| 用户想完成的事 | 产品回应 |
|---|---|
| "把碎片学习拼成一条有先后依赖的路" | 3 年路线图 + 10 阶段 + 17 模块前置依赖 |
| "确认我真的学会了，而不是看过了" | 章节小测 + 模块测验达标点亮（双轨完成，ADR-009） |
| "练到手，不是纸上谈兵" | WSL 真实环境实验/作业（命令级环境检查） |
| "考前有节奏地练" | 模拟考试（随机组卷/限时/自动交卷） |
| "拿到能给别人看的证明" | 结业证书 + 学习报告（诚实标注证据等级） |

## 竞品对照

| 维度 | 视频课程平台（极客时间等） | 刷题/记忆卡（Anki 等） | 免费文档（菜鸟教程等） | **本产品** |
|---|---|---|---|---|
| 内容组织 | 课程孤立，路径自组 | 卡片孤立，内容自建 | 碎片，无路径 | **3 年路线图贯穿 17 模块** |
| 掌握验证 | 章节自测（不计入任何凭证） | 记忆曲线复习 | 无 | **测验达标点亮 + 证据分级报告** |
| 实操 | 少量在线 lab | 无 | 代码示例 | **WSL 真实环境命令级检查** |
| AI | 平台内置（内容固定） | 插件 | 无 | **BYOK：判卷/精讲/答疑，可换服务商** |
| 成本 | 订阅制 | 免费 | 免费 | **免费 + 离线 + 数据自持** |
| 弱点（诚实） | — | — | — | 无真人答疑社区；无服务端同步；内容单人维护 |

## 北极星指标与度量设计

**北极星：验证达标模块数（Verified Modules per Learner）**——不是阅读进度、不是活跃天数：只有"测验 ≥80 分"才计入。这与双轨完成机制（ADR-009）天然自洽：产品把最想度量的东西设计成了最可信的信号。

| 层级 | 指标 | 现有度量手段 |
|---|---|---|
| 北极星 | 验证达标模块数 | 仪表盘"测验达标模块"计数 + 学习报告 |
| 激活 | 新用户首次完成测验 | 测验 attempts 首条记录 |
| 深度 | 各模块最佳分分布 / 错题消化率（错题进出比） | 仪表盘成绩区 + 错题本计数 |
| 留存 | 连续学习天数（番茄钟使用） | 学习统计（CLI stats / 会话记录） |

> 边界诚实：纯本地架构下无法跨用户聚合度量（这是隐私换洞见的主动取舍，见 ADR-002 数据自持）。度量设计为"单用户可自查 + 作者自用 dogfooding"。

## 人机分工实录（AI 结对开发中"人的决策"）

本项目 70%+ 实现由 AI 辅助完成，但关键产品决策由人提出或否决——以下均有 ADR/git 历史可查证：

1. **人质疑自报完成 → 双轨机制**：人提出"用户是否学完不应由自己点按钮说了算，应按题目效果"，AI 分析后指出题库粒度（模块级）与章节粒度不匹配的硬约束，双方讨论定为"测验达标自动点亮 + 手动标记保留"的双轨并存（ADR-009）。
2. **人追问刷课漏洞 → 证据分级报告**：人提出"被安排学习的人点按钮就能刷课"，AI 否决了"堵按钮/停留时长"方案（伪安全），人采纳"让自报与验证在报告中不可混淆"的呈现层方案（ADR-011）。
3. **人的审计直觉 → 按需对抗审计**：人提出 AI 判分加"对抗审计+裁决"，AI 质疑全面三轮=3 倍成本解决大多可免费解决的问题，最终定型为"审计只挂在判错方向"的分层判分（ADR-010）。
4. **人的验收质疑 → 工程护栏**：人两次点名验收质量（"缩略图式检查""UI 还不够好用"），催生"真截图双断点走查"规约与后来的 E2E 自动化（坑 7/9/10 皆由此实抓）。
5. **人的面试官视角 → 题库效度护栏**：人要求"以面试官视角挑最尖锐的缺点"，审计发现 7 套题库正确答案索引失衡（连点同一选项可刷分），随即把"索引分布校验"固化为 npm test 拦截项（见 [question-audit.md](./question-audit.md)）。

## 迭代节奏

v2.1 能用基线 → v2.2 工程化（单进程/隐私整改/进度闭环/备份）→ v2.3 内容全覆盖（17 模块无空白）→ 作品化上线（CI/Pages/ADR/复盘）→ v2.5 Web 测验 + BYOK AI 判卷 → v2.6 题库全模块 + 主观题 → v2.7 账户安全 + 学习闭环 + E2E → v2.8 题库效度审校与门面刷新。完整变更见 [迁移文档](../迁移文档.txt)，每个"做了什么+为什么"见 git 提交历史。

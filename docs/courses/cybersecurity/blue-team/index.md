# 🔵 蓝队专项：安全防御与事件响应

蓝队负责防御——搭建安全架构、监控异常、响应安全事件。**大多数安全工程师的日常工作就是蓝队工作。**

## 蓝队核心能力矩阵

```
          安全架构设计
          ／      ＼
         ／安全运营中心＼
        ／  (SOC)       ＼
安全监控 ──────────────── 事件响应
        ＼              ／
         ＼  威胁狩猎   ／
          ＼          ／
           合规与审计
```

## 1. 安全监控 (Security Monitoring)

### SIEM 系统搭建

```yaml
日志源:
  - 网络设备 (防火墙、路由器、交换机)
  - 服务器 (Linux /var/log/*, Windows Event Log)
  - 应用 (Nginx access.log, 数据库审计日志)
  - 安全设备 (IDS/IPS、WAF)

SIEM工具:
  开源: Wazuh (免费、功能完整、自带Elasticsearch)
  开源: Security Onion (集成化的安全监控发行版)
  开源: ELK + ElastAlert (自建告警)
  商业: Splunk (免费版每天500MB)
```

### 关键监控指标

| 场景 | 监控内容 | 告警阈值 |
|------|---------|---------|
| 暴力破解 | SSH/RDP 登录失败次数 | 5分钟 >10次 |
| 异常登录 | 非工作时间/异常地理位置登录 | 任何 |
| 权限提升 | 新sudoers、su/root使用 | 每次告警 |
| 数据外传 | 异常大流量出站 | >基准值2倍 |
| 恶意软件 | 已知恶意IP/域名通信 | 每次命中 |

## 2. 事件响应 (Incident Response)

### NIST 事件响应框架

```
准备 → 检测与分析 → 遏制与清除 → 恢复 → 事后总结
(Prepare)(Detect&Analyze)(Contain&Eradicate)(Recover)(Lessons Learned)
```

### 响应流程速查

**检测到可疑活动时——前15分钟该干什么：**

```
0-5分钟:   确认是否真的安全事件（不是误报）
           - 检查告警日志的上下文
           - 验证时间戳、来源IP是否可疑

5-10分钟:  评估严重程度 (Severity 1-4)
           - Sev1: 核心系统被攻破/数据正在泄露
           - Sev2: 非核心系统被攻破
           - Sev3: 可疑但未确认
           - Sev4: 低风险异常

10-15分钟: 启动响应
           - Sev1: 立即通知安全负责人、考虑隔离系统
           - 记录所有操作（谁、什么时间、做了什么）
           - 保护证据（不要关机！内存中证据会丢失）
```

### 证据获取顺序（挥发性顺序）

```
1. 内存镜像     (最易失，关机就没了)  — 用 LiME/Volatility
2. 网络连接状态  (netstat/ss)         — 当前连接马上变
3. 运行进程      (ps)                 — 进程可能被kill
4. 文件系统      (dd/tar)              — 相对稳定
5. 日志文件      (已写入磁盘)          — 最稳定但可能被删
```

## 3. 威胁狩猎 (Threat Hunting)

不是等告警来，而是主动在环境中寻找可能已经绕过防御的攻击者。

### 狩猎假设驱动方法

```
假设: "攻击者可能通过钓鱼邮件获取了某员工的凭证，
      正在内网横向移动"

验证方法:
1. 检查该员工账号的登录日志 — 有无异常时间/地点的登录？
2. 查看该员工电脑的网络连接 — 有否扫描内网的行为？
3. 检查AD审计日志 — 近期有新的高权限用户被创建吗？
```

## 4. 安全基线

### Linux 安全加固检查清单

```bash
# 1. 用户和密码策略
cat /etc/shadow | grep -v '!!' | grep -v '*'  # 所有有密码的账号
grep '^PASS_MAX_DAYS' /etc/login.defs          # 密码90天过期 ✅
grep '^minlen' /etc/security/pwquality.conf     # 密码最小长度>=12 ✅

# 2. SSH 配置
grep '^PermitRootLogin' /etc/ssh/sshd_config   # 应为 no 或 prohibit-password
grep '^PasswordAuthentication' /etc/ssh/sshd_config  # 应为 no (仅密钥登录)
grep '^Port' /etc/ssh/sshd_config              # 不用默认22端口

# 3. 不必要的服务
systemctl list-units --type=service --state=running | wc -l  # 服务越少越好
# 禁用不需要的服务: telnet, ftp, rsh...

# 4. 防火墙
iptables -L -n -v                                # 有规则吗？
# 默认策略应为 DROP，只开放必要端口

# 5. 审计
systemctl is-active auditd                       # 审计服务是否运行
# 配置 auditd 监控关键文件变动
```

## 蓝队 vs 红队：选哪个？

| | 🔵 蓝队 | 🔴 红队 |
|------|---------|---------|
| **日常工作** | 监控、加固、响应 | 测试、扫描、攻破 |
| **适合性格** | 细心、有条理、爱分析 | 好奇、创造力强、爱突破 |
| **入门难度** | ⭐⭐⭐ | ⭐⭐⭐⭐ |
| **岗位数量** | 多 | 相对少 |
| **薪资水平** | 中高 | 高 |
| **推荐第一证** | Security+ | CEH → OSCP |

**大多数人的路径**：先做蓝队打基础（1-2年），再决定是否转红队。不打好防守基础就直接学攻击，是悬在空中。

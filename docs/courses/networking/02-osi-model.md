# OSI 七层模型

## 为什么需要分层？

想象你要从北京寄一个包裹到上海：
1. 你把物品**打包**进箱子 📦（封装）
2. 写上**地址和收件人** 📝（寻址）
3. 交给快递员 🚚（传输）
4. 快递经过多个**中转站**（路由）
5. 到达目的地，**拆箱**取出物品（解封装）

网络通信也是类似的过程！OSI 模型把这个过程分为 7 层，每层各司其职。

## 七层速览

```
┌─────────────────────────────────────────────┐
│  7. 应用层 (Application)    HTTP, DNS, SMTP  │  ← 用户看到的
│  6. 表示层 (Presentation)   SSL/TLS, 编码    │  ← 加密/压缩/转码
│  5. 会话层 (Session)        NetBIOS, RPC     │  ← 建立/维护/断开连接
│  4. 传输层 (Transport)      TCP, UDP         │  ← 可靠传输/端口
│  3. 网络层 (Network)        IP, ICMP         │  ← 寻址/路由
│  2. 数据链路层 (Data Link)   MAC, 交换机      │  ← 帧/局域网
│  1. 物理层 (Physical)       网线, 光纤, 电信号 │  ← 0和1的传输
└─────────────────────────────────────────────┘
```

**记忆口诀**：**"物数网传会表应"** — 从下往上记。

也可以用英文首字母：**"Please Do Not Throw Sausage Pizza Away"**
(Physical, Data Link, Network, Transport, Session, Presentation, Application)

## 逐层详解

### 第1层：物理层

**核心问题**：如何在物理介质上传输 0 和 1？

- 网线（双绞线）：电信号
- 光纤：光信号
- WiFi：电磁波
- **集线器 (Hub)** 工作在这一层

**IT 工程师需要知道**：
- 网线类型：Cat5e (千兆)、Cat6 (万兆短距离)、Cat6a (万兆长距离)
- 光纤类型：单模（远距离）、多模（短距离）
- 常见故障：网线水晶头接触不良、光模块不匹配

### 第2层：数据链路层

**核心问题**：在同一个局域网内，如何标识和传输数据？

关键概念：
- **MAC 地址**：48位物理地址，全球唯一（如 `aa:bb:cc:dd:ee:ff`）
- **帧 (Frame)**：这一层的数据单元
- **交换机 (Switch)**：工作在这一层，根据 MAC 地址转发
- **ARP 协议**：根据 IP 地址查找 MAC 地址

**实战操作**：
```bash
# 查看本机 MAC 地址
ip link show

# 查看 ARP 表（IP 到 MAC 的映射）
arp -a

# 在 Windows 中
arp -a
```

### 第3层：网络层

**核心问题**：跨网络通信——数据如何从北京到上海？

关键概念：
- **IP 地址**：逻辑地址（如 `192.168.1.1`）
- **数据包 (Packet)**：这一层的数据单元
- **路由器 (Router)**：工作在这一层，根据 IP 地址转发
- **ICMP 协议**：`ping` 命令使用的协议
- **IP 路由**：决定数据包走哪条路

**实战操作**：
```bash
# 查看本机 IP 地址
ip addr show

# 查看路由表
ip route show

# 追踪数据包路径
tracert google.com    # Windows
traceroute google.com # Linux
```

### 第4层：传输层

**核心问题**：如何保证数据可靠（或不那么可靠但很快）地到达？

两个核心协议：

| 特性 | TCP | UDP |
|------|-----|-----|
| 连接方式 | 面向连接（三次握手）| 无连接 |
| 可靠性 | 可靠（确认+重传）| 不可靠（尽力而为）|
| 顺序 | 保证有序 | 不保证 |
| 速度 | 慢 | 快 |
| 典型应用 | HTTP、SSH、FTP | DNS、视频直播、游戏 |

**端口**：标识同一台机器上的不同服务
- `:80` — HTTP 网站
- `:443` — HTTPS 加密网站
- `:22` — SSH 远程登录
- `:53` — DNS 域名解析
- `:3306` — MySQL 数据库

**实战操作**：
```bash
# 查看本机开放的端口
netstat -tlnp   # Linux
netstat -ano    # Windows

# 测试某个端口是否可达
telnet google.com 80
# 或者
nc -zv google.com 80
```

### 第5层：会话层

管理通信会话的建立、维护和终止。在现代网络中，这一层的功能大多被传输层和应用层吸收。

### 第6层：表示层

数据格式转换、加密/解密、压缩/解压缩。
- **SSL/TLS**：HTTPS 的加密就发生在这里
- 字符编码：ASCII → UTF-8
- 图片格式转换：PNG → JPEG

### 第7层：应用层

**用户直接看到的一层**。提供网络服务接口。

- **HTTP/HTTPS**：浏览网页
- **SMTP/POP3/IMAP**：收发邮件
- **DNS**：域名解析（虽然它也是这层的协议，但服务于下层）
- **SSH**：安全远程登录
- **FTP/SFTP**：文件传输

## 封装与解封装：数据如何"旅行"

```
发送端（封装）：
应用层: [HTTP请求: "GET /index.html"]
  ↓ 加上TCP头（端口号）
传输层: [TCP头 | HTTP请求]
  ↓ 加上IP头（IP地址）
网络层: [IP头 | TCP头 | HTTP请求]
  ↓ 加上MAC头（MAC地址）+ 帧尾
链路层: [MAC头 | IP头 | TCP头 | HTTP请求 | FCS]

接收端（解封装）：逐层拆包，反向操作
```

每一层只看自己的"头"，不关心里面装了啥——这就是封装的精髓。

## 动手实验：观察封装

在 WSL2 中安装并运行 `tcpdump`（需要管理员权限）：

```bash
# 抓取访问某个网站时的数据包
sudo tcpdump -i eth0 -n port 80 -c 10

# 然后在另一个终端中：
curl http://example.com
```

观察输出，你能看到数据包的分层结构吗？

## 自测题

1. 路由器工作在哪一层？交换机和集线器呢？
2. TCP 为什么比 UDP 慢？它多了什么操作？
3. 数据从应用层到物理层，每经过一层会加上什么？

<details>
<summary>点击查看答案</summary>

1. 路由器 = 第3层（网络层，根据IP转发）；交换机 = 第2层（数据链路层，根据MAC转发）；集线器 = 第1层（物理层，广播到所有端口）
2. TCP 的三次握手建立连接、确认应答机制（ACK）、重传丢失的包、流量控制和拥塞控制，这些机制保证了可靠性但增加了延迟
3. 经过传输层加上 TCP/UDP 头（端口号），经过网络层加上 IP 头（IP地址），经过数据链路层加上 MAC 头和帧尾
</details>

# 03 - 系统启动故障排查

## 计算机启动全过程

```
按下电源键
    │
    ▼
┌──────────────────────────────────────────────┐
│ ① BIOS/UEFI 自检 (POST)                       │

                   │
                   ▼

                   │
                   ▼
```

## 故障阶段一：开机无显示 (POST 失败)

### 蜂鸣声诊断表

不同品牌主板的蜂鸣声含义不同，以下是常见情况：

| 蜂鸣模式 | AMI BIOS | Award BIOS | Phoenix BIOS |
|---------|----------|------------|--------------|
| 1短 | 内存刷新失败 | 正常启动 | 正常启动 |
| 1长2短 | 显卡错误 | 显卡错误 | - |
| 1长3短 | 内存错误 | 显卡错误 | - |
| 连续短响 | 电源问题 | 内存错误 | - |
| 连续长响 | 内存未插好 | 显卡未插好 | - |
| 2短 | 内存奇偶校验错误 | CMOS设置错误 | - |
| 无蜂鸣声 | 电源/主板/CPU问题 | 电源/主板问题 | 电源/主板问题 |

### POST 失败排查流程

```
开机完全无显示 + 无蜂鸣声
    │
    ├── 检查外部：电源线、显示器、排插
    │
    ├── 最小系统法：只保留 CPU + 主板 + 1根内存 + 电源
    │   ├── 能启动 → 逐一加回部件排查
    │   └── 不能启动 → 问题在 4 大件之一
    │
    └── 替换法：依次替换电源→主板→CPU
         （CPU 极少损坏，放最后排查）
```

### 实战：清除 CMOS 恢复 BIOS 默认设置

```
适用场景：超频失败、BIOS设置错误导致无法开机

方法一（推荐）：拔掉 CMOS 电池
1. 断开电源
2. 找到主板上圆形银色电池（CR2032）
3. 轻轻拨开卡扣，取出电池
4. 等待 30 秒 - 1 分钟
5. 装回电池
6. 接通电源，开机（BIOS 已恢复出厂设置）

方法二：短接 CMOS 跳线
1. 断开电源
2. 找到主板上标有 CLR_CMOS 或 JBAT1 的跳线
3. 用螺丝刀短接两个针脚 5-10 秒
4. 开机

方法三：部分主板有 Clear CMOS 按钮，直接按一下即可
```

## 故障阶段二：卡在启动画面 / 无法引导

### 常见启动阶段报错信息

| 错误信息 | 含义 | 处理 |
|---------|------|------|
| `Boot Device Not Found` | 找不到启动设备 | 检查硬盘连接/启动顺序 |
| `No Bootable Device` | 无可引导设备 | 检查系统是否损坏 |
| `BOOTMGR is missing` | Windows 引导管理器丢失 | 需要修复引导 |
| `Operating System not found` | 找不到操作系统 | 硬盘故障或引导损坏 |
| `INACCESSIBLE_BOOT_DEVICE` | 无法访问启动设备(蓝屏) | 驱动问题/硬盘模式改变 |
| `Disk read error occurred` | 磁盘读取错误 | 硬盘可能有坏道 |
| `Reboot and Select proper Boot device` | 未找到操作系统 | 检查启动顺序/硬盘是否识别 |

### 实战：修复 Windows 引导

```powershell
# 需要 Windows 安装 U盘 或 恢复盘

# 方法一：自动修复
# 1. U盘启动 → 选择"修复计算机" → "疑难解答" → "启动修复"
# 2. 系统会自动检测并修复引导问题

# 方法二：命令行手动修复
# U盘启动 → "修复计算机" → "疑难解答" → "命令提示符"

# 传统 BIOS (MBR 分区)：
bootrec /fixmbr       # 修复主引导记录
bootrec /fixboot      # 修复引导扇区
bootrec /scanos       # 扫描已安装的 Windows
bootrec /rebuildbcd   # 重建 BCD 配置

# UEFI (GPT 分区)：
diskpart
list disk             # 找到系统盘
select disk 0
list volume           # 找到 EFI 分区（通常 100MB FAT32）
select volume 2       # 选择 EFI 分区
assign letter=Z       # 分配盘符
exit
bcdboot C:\Windows /s Z: /f UEFI   # 重建 UEFI 引导
```

## 故障阶段三：蓝屏死机 (BSOD)

### 蓝屏信息怎么看？

```
Windows 蓝屏核心信息：
┌──────────────────────────────────────────┐
│ :(  你的电脑遇到问题，需要重新启动。      │
│                                          │
│ 停止代码: MEMORY_MANAGEMENT               │ ← 这个最重要！
│                                          │
│ 如果致电支持人员，请提供以下信息：        │
│ 停止代码: MEMORY_MANAGEMENT               │
│                                          │
│ 你可以搜索: MEMORY_MANAGEMENT             │
└──────────────────────────────────────────┘
```

### 常见蓝屏停止代码速查

| 停止代码 | 常见原因 | 排查方向 |
|---------|---------|---------|
| `MEMORY_MANAGEMENT` | 内存故障 | 运行内存诊断工具 |
| `IRQL_NOT_LESS_OR_EQUAL` | 驱动冲突/内存损坏 | 更新驱动/内存检测 |
| `CRITICAL_PROCESS_DIED` | 关键系统进程崩溃 | 检查系统文件/SFC |
| `SYSTEM_SERVICE_EXCEPTION` | 驱动或系统文件错误 | 分析 .dmp 文件 |
| `KERNEL_SECURITY_CHECK_FAILURE` | 驱动/软件冲突 | 最近装的软件/驱动 |
| `DRIVER_OVERRAN_STACK_BUFFER` | 驱动缓冲区溢出 | 更新/卸载问题驱动 |
| `NTFS_FILE_SYSTEM` | 硬盘/文件系统问题 | chkdsk /f |
| `UNEXPECTED_STORE_EXCEPTION` | 硬盘响应超时 | 检查硬盘健康状态 |
| `PAGE_FAULT_IN_NONPAGED_AREA` | 内存/硬盘问题 | 内存检测 + 硬盘检测 |
| `DPC_WATCHDOG_VIOLATION` | SSD 固件/驱动问题 | 更新 SSD 固件 |
| `VIDEO_TDR_FAILURE` | 显卡驱动超时 | 更新/回滚显卡驱动 |
| `WHEA_UNCORRECTABLE_ERROR` | 硬件故障 | CPU/主板/RAM 硬件问题 |

### 实战：分析蓝屏转储文件

```powershell
# 1. 确认转储文件位置
# 文件通常位于：C:\Windows\Minidump\
# 或 C:\Windows\MEMORY.DMP

# 2. 使用系统自带工具查看历史蓝屏
# 搜索"查看可靠性历史记录" → 打开 → 点击红色错误事件

# 3. 使用 BlueScreenView (免费工具) 分析 .dmp 文件
# 官网: nirsoft.net/utils/blue_screen_view.html
# 可以直观显示每个蓝屏的驱动和错误代码
```

### 蓝屏排查三步法

```
步骤1：回忆"最近做了什么"
  → 安装了新软件？更新了驱动？加了新硬件？
  → 80% 的蓝屏与最近的变更有关

步骤2：看蓝屏代码
  → MEMORY → 先跑内存诊断
  → DRIVER → 进入安全模式卸载最近安装的驱动
  → NTFS → chkdsk 检查硬盘

步骤3：安全模式排除法
  → 连续开机失败 3 次 → 自动进入"高级启动选项"
  → 或开机时按 F8 / Shift+F8
  → 选择"安全模式" → 如果能正常进安全模式
    → 问题大概率是驱动/软件引起，不是硬件
```

## 故障阶段四：进入系统后异常

### 系统卡顿/响应缓慢

```
排查清单：
□ 任务管理器 → 查看 CPU/内存/磁盘 使用率
  → CPU 持续 100% → 打开"详细信息"找到占用进程
  → 内存 90%+ → 加内存或关闭占用大的程序
  → 磁盘 100% → 可能是 HDD 性能瓶颈或硬盘故障

□ 查看"启动"选项卡 → 禁用不必要的自启动程序

□ 用 CrystalDiskInfo 检查硬盘健康
  → HDD 如果有坏道会造成大量重试，拖慢整个系统

□ 检查 Windows Update 是否在后台运行
  → 服务管理器 → 停止 Windows Update 服务（排查用）
```

### 系统频繁卡死/冻结

```
症状：鼠标能动但点击无反应，或完全卡死

排查顺序：
1. Ctrl+Shift+Esc → 任务管理器 → 查看是否某个进程"未响应"
2. 事件查看器 (eventvwr.msc) → Windows日志 → 系统
   → 查找卡死时段的红色"关键"和"错误"事件
3. 检查温度 → 可能是散热问题导致间歇性降频
4. 电源选项 → 改为"高性能"排查是否电源管理问题
5. sfc /scannow → 修复系统文件
6. 重装/更新显卡驱动
```

### 重要系统修复命令

```powershell
# 系统文件检查（最常用）
sfc /scannow

# DISM 修复系统映像（sfc 不行时用这个）
DISM /Online /Cleanup-Image /RestoreHealth

# 检查磁盘文件系统
chkdsk C: /f /r
# /f = 修复文件系统错误
# /r = 查找坏扇区（耗时长）

# 检查并修复 Windows 组件存储
DISM /Online /Cleanup-Image /CheckHealth
DISM /Online /Cleanup-Image /ScanHealth
DISM /Online /Cleanup-Image /RestoreHealth
```

### 实战：使用系统还原

```
系统还原是 Windows 的"时光机"——回到之前正常工作的状态

前提：系统保护功能已开启（默认 C 盘开启）

操作：
1. 搜索 "创建还原点" → 打开系统属性
2. 点击 "系统还原" → 选择一个还原点（按日期选择）
3. 点击 "扫描受影响的程序" → 查看哪些程序会被移除
4. 确认 → 开始还原（过程约 10-30 分钟，期间会自动重启）

注意：系统还原不会影响你的个人文件（文档、照片等），
      只还原系统文件、注册表和驱动程序。
```

## Windows 高级启动选项

### 如何进入高级启动

```
方法1：按住 Shift 键再点"重启"
方法2：开机时按 F11（部分品牌）
方法3：连续 3 次开机失败自动进入
方法4：设置 → 更新和安全 → 恢复 → 高级启动 → 立即重启
```

### 各选项说明

| 选项 | 用途 | 何时使用 |
|------|------|---------|
| 启动修复 | 自动修复引导问题 | 无法启动时首选 |
| 安全模式 | 仅加载基本驱动和服务 | 排查驱动/软件问题 |
| 带网络的安全模式 | 安全模式 + 网络功能 | 需要联网下载驱动 |
| 命令提示符 | 进入命令行修复 | 手动修复引导/系统 |
| 卸载更新 | 移除最近的质量更新 | 更新后出问题 |
| 系统还原 | 回到之前的还原点 | 系统异常前有还原点 |
| 系统映像恢复 | 从完整备份恢复 | 有做系统映像备份 |
| UEFI 固件设置 | 进入 BIOS/UEFI | 修改启动顺序等 |

## 自测题

1. 开机后看到 `BOOTMGR is missing`，应该怎么做？
2. 蓝屏代码 `MEMORY_MANAGEMENT` 应该最先排查什么？
3. 电脑开机黑屏但风扇在转，没有任何蜂鸣声，可能是什么问题？
4. `sfc /scannow` 和 `DISM /RestoreHealth` 有什么区别？
5. 系统能进入安全模式但正常模式蓝屏，这说明什么？

<details>
<summary>点击查看答案</summary>

1. **使用 Windows 安装 U盘启动 → 修复计算机 → 命令提示符 → 运行 `bootrec /fixmbr`, `bootrec /fixboot`, `bootrec /rebuildbcd`。UEFI 系统则用 `bcdboot` 重建引导**
2. **内存故障**。先重新插拔内存+橡皮擦擦金手指 → 运行 `mdsched.exe` 内存诊断 → 单根测试定位坏内存
3. **可能是电源、主板或 CPU 故障**。先用最小系统法（CPU+主板+1根内存+电源）测试。如果能启动，说明被拔掉的某个部件有问题。如果仍不能启动，用替换法逐个排查
4. **`sfc /scannow`** 检查并修复 Windows 系统文件（从本地缓存）；**`DISM /RestoreHealth`** 从 Windows Update 或指定源修复系统映像（sfc 的"上级"，sfc 修不了的，先用 DISM 修复映像源，再跑 sfc）
5. **问题大概率是第三方驱动或软件引起的**。安全模式只加载核心系统驱动，所以能正常运行 → 说明基础硬件和系统本身没问题 → 进安全模式卸载最近安装的驱动和软件
</details>

# 02 - 网页访问异常排查

## 快速判断问题范围

```
用户说："网页打不开"

第一步：二分法确定问题范围
┌─────────────────────────────────────────────┐
│ 所有网站都打不开？  还是  只有某个网站打不开？  │
│                                             │
│ 所有打不开 → 网络/DNS/代理/浏览器问题         │
│ 单个打不开 → 那个网站的问题 或 被防火墙拦截    │
└─────────────────────────────────────────────┘

第二步：排除法确定问题类型
┌─────────────────────────────────────────────┐
│ QQ/微信能正常收发消息吗？                     │
│ ✅ 能 → 大概率是 DNS 或代理问题               │
│ ❌ 不能 → 网络连通性有问题（回第1章）          │
└─────────────────────────────────────────────┘
```

## 场景一：所有网站都打不开

### 完整排查流程

```
所有网页打不开
        │
        ▼
   ┌─ 1. 检查浏览器本身 ──────────────────────┐
   │  换个浏览器试试？（Chrome → Edge）         │
   │  无痕/隐私模式试试？                        │
   └────────────────┬──────────────────────────┘
                    │ 换浏览器也不行
                    ▼
   ┌─ 2. 检查代理设置 ────────────────────────┐
   │  Windows设置 → 网络和Internet → 代理     │
   │  是否开启了不该开的代理？                   │
   │  使用代理脚本？脚本地址是否可达？           │
   └────────────────┬──────────────────────────┘
                    │ 代理正常
                    ▼
   ┌─ 3. 检查 DNS ───────────────────────────┐
   │  nslookup baidu.com                      │
   │  能解析吗？解析结果正确吗？                │
   └────────────────┬──────────────────────────┘
                    │ DNS 正常
                    ▼
   ┌─ 4. 检查防火墙/安全软件 ──────────────────┐
   │  临时关闭 Windows 防火墙测试               │
   │  临时关闭杀毒软件测试                      │
   └────────────────┬──────────────────────────┘
                    │
                    ▼
   ┌─ 5. 检查 hosts 文件 ────────────────────┐
   │  C:\Windows\System32\drivers\etc\hosts  │
   │  有没有异常条目？                          │
   └──────────────────────────────────────────┘
```

### 代理设置检查

```powershell
# 查看当前代理设置
netsh winhttp show proxy

# 查看 Internet 选项中的代理（IE/Edge 用）
# 运行 → inetcpl.cpl → 连接 → 局域网设置

# 常见的代理问题：
# 1. "使用代理服务器"被意外勾选 → 取消勾选
# 2. "自动检测设置"导致慢 → 取消勾选测试
# 3. PAC 脚本地址失效 → 更新或移除
```

### Hosts 文件检查

```powershell
# 查看 hosts 文件
notepad C:\Windows\System32\drivers\etc\hosts

# 正常 hosts 文件内容应只有：
# 127.0.0.1       localhost
# ::1             localhost

# 异常特征：
# - 出现大量域名和 IP 的对应关系
# - baidu.com、google.com 等被指向奇怪的 IP
# - 文件很大，有几百行
# → 可能被恶意软件/广告软件篡改！
```

## 场景二：网页加载异常慢

### "慢"的排查维度

```
⏱ 网页加载慢 ≠ 网络慢

先判断"慢"在哪个阶段：
```

```
┌──────────────────────────────────────────────────┐
│ 用户在浏览器输入 baidu.com 并回车                  │
│                                                  │
│ ① 查找阶段：浏览器找 DNS → TCP 连接 → TLS 握手     │
│    ↓ 这个阶段慢 = DNS/网络延迟问题                 │
│                                                  │
│ ② 等待阶段：服务器处理请求 → 返回 HTML            │
│    ↓ 这个阶段慢 = 服务器性能问题                   │
│                                                  │
│ ③ 加载阶段：浏览器下载 CSS/JS/图片等资源           │
│    ↓ 这个阶段慢 = 带宽不足/资源太大/CDN问题         │
│                                                  │
│ ④ 渲染阶段：浏览器解析并渲染页面                  │
│    ↓ 这个阶段慢 = 浏览器/电脑性能问题              │
└──────────────────────────────────────────────────┘
```

### 浏览器开发者工具排查法（F12）

```
在浏览器中按 F12 → Network（网络）标签 → 刷新页面

关键指标解读：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DOMContentLoaded: 1.2s  → HTML 解析完成时间
Load: 3.5s              → 所有资源加载完成时间

看每个资源的"Time"列：
- Queueing 大 → 浏览器连接数限制
- DNS Lookup 大 → DNS 解析慢
- Initial connection 大 → 到服务器的网络延迟大
- TTFB (Time To First Byte) 大 → 服务器响应慢
- Content Download 大 → 文件太大或带宽不足

看 Status 列：
- 200 → 正常
- 301/302 → 重定向（过多重定向会拖慢加载）
- 304 → 从缓存加载（快）
- 404 → 资源找不到（不影响页面，看是不是关键资源）
- 500 → 服务器内部错误
```

### 常见网页加载慢原因

| 原因 | 症状 | 处理 |
|------|------|------|
| DNS 解析慢 | 显示"正在解析主机..."很久 | 换 DNS 服务器 |
| 代理设置 | 显示"正在连接代理..." | 检查/关闭代理 |
| MTU 问题 | 部分网站慢或打不开 | 调整 MTU |
| 带宽被占满 | 所有网站都慢 | 查谁在占用带宽 |
| 浏览器缓存/插件 | 换浏览器就正常 | 清理缓存/禁用插件 |
| 安全软件扫描 | 关闭安全软件后正常 | 调整安全软件设置 |

### MTU 检测与调整

```powershell
# MTU (Maximum Transmission Unit) — 最大传输单元
# 如果 MTU 设置过大，数据包在路径中被分片会导致速度下降或部分网站打不开

# 检测最佳 MTU：
ping 8.8.8.8 -f -l 1472
# -f = 禁止分片
# -l 1472 = 数据包大小（加上 28 字节的 IP+ICMP 头 = 1500）
# 如果返回"需要拆分"→ 减小数值
# 如果 ping 通 → 这个值是可用的最大 MTU

# 常见 MTU 值：
# 以太网：1500（默认）
# PPPoE（拨号）：1492
# VPN：根据协议不同，通常需降低

# 修改 MTU：
netsh interface ipv4 show interfaces          # 查看接口索引
netsh interface ipv4 set subinterface 接口索引 mtu=1492 store=persistent
```

## 场景三：HTTPS/证书错误

### 常见证书错误

| 错误信息 | 含义 | 处理 |
|---------|------|------|
| `NET::ERR_CERT_DATE_INVALID` | 证书过期 | 检查电脑时间是否正确！ |
| `NET::ERR_CERT_AUTHORITY_INVALID` | 证书颁发者不被信任 | 自签名证书/内部CA未安装 |
| `NET::ERR_CERT_COMMON_NAME_INVALID` | 证书域名不匹配 | 访问的域名和证书上的不一致 |
| `NET::ERR_CERT_REVOKED` | 证书已被吊销 | 网站证书被吊销，不要继续访问 |
| `SSL_ERROR_BAD_CERT_DOMAIN` | 证书域名错误 | 同 COMMON_NAME_INVALID |

### 第一步：检查系统时间！

```
⚠️ 这是最常见也最容易忽略的原因！

电脑时间如果偏差超过证书的有效期范围 → 浏览器认为证书无效

检查：
1. 看任务栏右下角时间是否准确
2. 日期、年份是否正确（年份错了非常常见！）
3. 设置 → 时间和语言 → 日期和时间 → "自动设置时间" 打开
4. 点击"立即同步"
```

### HTTPS 排查其他步骤

```
1. 系统时间确认正确后仍报错？

2. 换个浏览器试试
   → Edge 报错但 Chrome 正常？→ 问题在浏览器
   → 都报错 → 问题在系统/网络层面

3. 检查是否使用了代理或 VPN
   → 代理/VPN 在做 SSL 中间人解密
   → 关闭代理/VPN 后测试

4. 检查是否安装了企业/学校的安全证书
   → 设置 → 搜索"管理计算机证书"
   → 受信任的根证书颁发机构 → 查看有无异常证书

5. 检查是否有安全软件在做 HTTPS 扫描
   → 卡巴斯基、ESET 等有 HTTPS 扫描功能
   → 临时关闭测试
```

## 场景四：特定浏览器问题

### Chrome/Edge 常见问题

```
症状：Chrome/Edge 无法上网，但其他浏览器可以

原因：通常是 Chrome/Edge 的用户配置文件损坏

处理：
1. 先试：设置 → 重置设置 → 将设置还原为原始默认设置

2. 不行：完全重置用户配置
   Chrome: 关闭Chrome → 重命名
   %LOCALAPPDATA%\Google\Chrome\User Data → User Data.old
   重启Chrome（会创建全新的配置文件）

   Edge类似：
   %LOCALAPPDATA%\Microsoft\Edge\User Data

3. 清理缓存和Cookie
   Ctrl+Shift+Delete → 时间范围选"所有时间" → 清除
```

### 浏览器插件排查

```
插件是常见的网页问题来源（广告拦截器、VPN插件等）

快速排查法：
1. 打开无痕/隐私窗口 → 插件默认不在无痕模式运行
   → 无痕模式正常 = 插件问题

2. 逐个禁用插件 → 找到出问题的那个

3. 常见问题插件：
   - 广告拦截器（误拦了正常内容）
   - VPN/代理插件（网络路由问题）
   - 下载管理器（拦截了请求）
   - 各种"安全"插件（过度拦截）
```

## 场景五：HTTP 状态码速查

```
浏览器报错或 F12 看到的状态码含义：

2xx 成功
  200 OK — 请求成功
  204 No Content — 成功但没有返回内容

3xx 重定向
  301 Moved Permanently — 永久重定向
  302 Found — 临时重定向
  304 Not Modified — 内容未修改（使用缓存）

4xx 客户端错误
  400 Bad Request — 请求格式错误
  401 Unauthorized — 需要登录认证
  403 Forbidden — 禁止访问（没权限）
  404 Not Found — 页面不存在
  405 Method Not Allowed — 请求方法不对（如用GET访问POST接口）
  408 Request Timeout — 请求超时
  429 Too Many Requests — 请求太频繁，被限流

5xx 服务端错误
  500 Internal Server Error — 服务器内部错误
  502 Bad Gateway — 网关错误（上游服务器返回无效响应）
  503 Service Unavailable — 服务暂时不可用（过载/维护）
  504 Gateway Timeout — 网关超时（上游服务器响应太慢）
```

### 常见 HTTP 错误处理

| 错误 | IT 工程师的处理 |
|------|----------------|
| 403 Forbidden | 检查 IP 是否被封锁、是否需要 VPN、身份认证 |
| 404 Not Found | 确认 URL 是否正确、资源是否被移动或删除 |
| 502 Bad Gateway | 检查反向代理/网关配置、后端服务是否运行 |
| 503 Service Unavailable | 服务是否在维护、是否过载、检查服务器状态 |
| 504 Gateway Timeout | 增加超时时间、检查后端响应性能 |

## 实战案例

### 案例1：网页打开后是空白

```
场景：用户反映"打开某个网站，页面一片空白"

排查：
1. 换浏览器 → 还是空白
2. 清除缓存 → 还是空白
3. F12 查看 Console → JavaScript 报错！
4. 查看 Network → 主要 JS 文件返回 404
5. 检查发现：CDN 域名被企业防火墙误拦截

处理：将 CDN 域名加入防火墙白名单
```

### 案例2：HTTPS 网站打不开

```
场景：某个 HTTPS 网站突然打不开，显示证书错误

排查：
1. 检查时间 → 时间正确
2. 点击证书查看详情 → 发现证书已过期 1 天
3. 用其他电脑/手机访问 → 同样证书过期
4. 结论：网站 SSL 证书过期（不是用户端的问题）

处理：联系网站管理员更新证书
临时方案（不推荐，仅紧急时）：确认安全的前提下，
       告知用户具体情况，等网站管理员处理
```

## 自测题

1. "QQ能上但网页打不开"通常是什么问题？
2. 浏览器报 `ERR_CERT_DATE_INVALID` 最先检查什么？
3. F12 开发者工具中 TTFB 很长说明什么？
4. HTTP 502 和 504 有什么区别？
5. 广告拦截器可能导致什么网页问题？

<details>
<summary>点击查看答案</summary>

1. **DNS 解析问题或代理问题**。QQ/微信等即时通讯软件通常使用 IP 直连或有自己的 DNS 解析机制，不依赖系统 DNS 设置。网页需要 DNS 解析，DNS 有问题时打不开，但 QQ 不受影响。也可能是代理设置错误（浏览器配置了代理但 QQ 不走代理）
2. **系统时间！** 检查任务栏时钟的日期和时间是否正确，尤其是年份。时间不对是最常见的证书错误原因。然后检查"自动设置时间"是否开启，手动同步一次
3. **服务器端响应慢**。TTFB (Time To First Byte) 是从发送请求到收到第一个字节的时间。TTFB 长说明网络延迟大或服务器处理慢。浏览器端排查不到更多信息，需要服务器端排查
4. **502 Bad Gateway** = 网关/代理服务器收到了上游服务器的无效响应（上游服务器可能崩溃或返回了格式错误的数据）。**504 Gateway Timeout** = 网关/代理在指定时间内没等来上游服务器的响应（超时了）。简单说：502 = 收到了但不对，504 = 压根没收到
5. **页面内容缺失、按钮点击无反应、表单提交失败、页面样式错乱**。广告拦截器可能误判正常的功能脚本或内容为广告，导致页面部分功能失效。无痕模式测试是最快的排查方法
</details>

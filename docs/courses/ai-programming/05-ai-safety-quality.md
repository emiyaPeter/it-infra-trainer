# 安全、质量与验证

AI 编程的效率红利背后是三重风险：**泄密、坏代码、坏依赖**。本章是把前面所有工作流兜底的最后一章——护栏不是限制效率，是让你敢跑得快。

## 1. 红线一：密钥与隐私

```text
❌ 把 .env 内容、数据库密码、API Key 粘贴到对话里
❌ 让云端 AI 阅读含客户数据/公司内网代码的项目
❌ 把个人真实姓名、手机号写进让 AI 处理的样例数据
```

正确姿势：

- 密钥**永远通过环境变量**注入，代码里只出现变量名——AI 不需要看到真值就能写对逻辑
- 给 AI 的样例数据用假数据（张三/13800138000 这种），真实数据脱敏后再给
- 公司代码用公司合规批准的工具；个人项目也别把 API Key 粘进任何云端对话
- **git 也一样是红线**：密钥进过 git 历史等于永久泄露（换密钥，别只删文件）

> 本项目就是活例子：`.env` 在 .gitignore 里、`users.json` 桥接文件曾把姓名手机号发布到静态目录——隐私边界要主动设计，不是默认就有。

## 2. 红线二：AI 代码的安全审查清单

AI 生成的代码要过一遍的**安全五问**：

| # | 检查点 | 危险写法示例 | 要求 |
|---|--------|--------------|------|
| 1 | 命令执行 | `exec(cmd + userInput)` | 永不拼接用户输入到 shell；用参数数组 |
| 2 | SQL | `"SELECT ... WHERE name='" + name + "'"` | 一律参数化查询 |
| 3 | 路径拼接 | `join(base, userInput)` 直接用 | 校验 `..` 越界（路径穿越） |
| 4 | 反序列化/eval | `eval(data)`、任意 JSON 反序列化 | 禁用；白名单解析 |
| 5 | 输出转义 | 模板直接插值到 HTML | 转义防 XSS |

**让 AI 自查**也是有效手段："请按上述五问审查你刚写的代码，逐条回答"——但自查结果仍要人扫一眼，AI 审 AI 会共盲。

## 3. 护栏一：测试是跑得快的前提

没有测试的 AI 高速开发 = 高速积累债务。护栏分层：

```text
第 1 层  语法/静态检查     node --check / eslint        （秒级）
第 2 层  冒烟测试          核心命令能跑、退出码 0        （秒级）
第 3 层  单元/集成测试     关键逻辑的正反用例            （分钟级）
第 4 层  构建验证          vitepress build / 打包        （分钟级）
```

落地建议：

- **第一天就建**，别等"代码写完再补测试"——护栏的价值在于改代码的时候
- 把 1、2、4 层合成一条 `npm test`（本培训系统就是这个结构：21 项语法 + 5 项 CLI 冒烟 + 构建产物校验）
- 让 AI 的规矩写进 AGENTS.md："任何改动必须 npm test 全绿"——代理会自己修到绿再交工，体验极好

## 4. 护栏二：依赖安全

AI 特别爱"顺手加依赖"。每个新包进项目前问三个问题：

1. **必要性**：标准库/现有依赖能不能做？（很多轮子 Node 自带）
2. **健康度**：周下载量、最近更新时间、issue 堆积情况
3. **许可**：GPL 类许可进商业项目要谨慎（法律问题不是技术问题）

配套动作：`npm audit` 定期跑；lockfile（package-lock.json）必须提交 git，保证你和 AI 装的是同一版本——**版本漂移是"我这能跑你那不能跑"的头号元凶**。

## 5. 责任边界：署名是你的

最后一条不是技术，是职业操守：

- **提交的是你的名字，责任就是你的**——"AI 写的"在任何事故复盘里都不构成免责
- AI 代码进了生产，你就是它的作者：review 的深度 = 你背责的深度
- 反过来，AI 也不夺走你的成长：**每个它给出的你不懂的写法，要么搞懂，要么不用**

## 常见误区

1. **"内部工具不用管安全"** ——攻击者的入口不区分你的工具定位；何况内部工具常驻着最高权限
2. **"AI 自查过就安全了"** ——共盲问题真实存在，安全清单必须人过目
3. **"测试以后再补"** ——以后 = 永不；护栏第一天建
4. **"lockfile 没必要提交"** ——没有它，AI 和你、今天和明天，装的依赖都可能是不同版本

## 小结

- 三条红线：密钥不落对话、安全五问过一遍、提交即署名
- 测试护栏分四层，第一天就建，规矩写进 AGENTS.md
- 依赖三问 + lockfile 提交，防供应链和版本漂移

## 练习（结业）

1. 给你的书签管理器补上第 1、2 层护栏（语法检查 + 冒烟脚本）
2. 用安全五问审查它的代码（特别是 `bm add <URL>` 的输入处理）
3. 写你自己的《AI 协作守则》：5 条红线 + 5 条习惯，贴在工位

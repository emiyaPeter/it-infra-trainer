# AI 终端代理工作流

终端代理（CLI Agent）是当前 AI 编程的最强形态：它能**自己读文件、跑命令、改代码、执行测试**，完成整个任务闭环。能力越大，"用对姿势"越重要——本章是一套经过实践验证的工作流。

## 预备课：终端 5 分钟速成

::: info 零基础同学看这里
终端（也叫命令行/CLI）就是**用打字代替鼠标**操作电脑的黑窗口。你只需要 6 条命令就能开始本章（学完第 2 章 Linux 课程后这里就是常识了）：

| 命令 | 作用 | 类比 |
|------|------|------|
| `pwd` | 我现在在哪个文件夹 | 看一眼定位 |
| `ls`（Windows: `dir`） | 这里有什么文件 | 打开文件夹看列表 |
| `cd 文件夹名` | 进入某文件夹 | 双击打开文件夹 |
| `cd ..` | 返回上一层 | 点返回 |
| `clear`（Windows: `cls`） | 清屏 | 让窗口干净点 |
| `Ctrl + C` | 强行停止当前命令 | 万能"急刹车" |

**怎么打开终端**：Windows 按 `Win 键` 输入 "PowerShell" 回车；或开始菜单 → Windows Terminal。打开后就是一个光标在闪的窗口——把命令打进去、回车，就这样。
:::

## 1. 四步循环：探索 → 计划 → 执行 → 验证

```
┌─────────────────────────────────────────────┐
│  1. 探索   让 AI 自己读懂项目再动手           │
│  2. 计划   要方案，人工审查，未批准不写码      │
│  3. 执行   小步进行，每步可检验               │
│  4. 验证   跑测试/构建，AI 自己修到绿          │
└─────────────────────────────────────────────┘
```

对应的提示节奏：

```text
① "先浏览项目结构和相关代码，不要修改任何东西。"
② "基于你看到的情况，给出改造方案和涉及文件清单，等我确认。"
③ "批准第 1 步，只做这一步。"
④ "跑 npm test，有失败就修复，直到全绿再停。"
```

**为什么必须这样**：代理拿到"把这个功能做了"的全权委托后，最常见的失败模式是一次性改十个文件，其中三处理解错了需求——你 review 的时候已经分不清哪改了哪没改。

## 2. 项目记忆：AGENTS.md / CLAUDE.md

主流代理都支持项目级的"记忆文件"（AGENTS.md、CLAUDE.md 等）：每次会话自动读取，相当于**给新人的一页入职须知**。值得写进去的内容：

```markdown
# AGENTS.md
- 技术栈：Node.js 20 ESM + VitePress + better-sqlite3
- 测试：改完代码必须跑 npm test（含语法+CLI 冒烟+构建）
- 数据红线：data/ 目录是用户真实数据，任何命令不得删除/覆盖
- 风格：中文注释；遵循现有命名；不引入新依赖需说明理由
- 已知坑：bat 必须保持 GBK 编码（UTF-8 会导致 cmd 解析错位闪退）
```

最后一条不是虚构——本项目就真的踩过这个坑。**把你踩过的坑写进记忆文件，AI 就不会陪你再踩一遍**。

## 3. 权限模式：默认最小授权

代理一般都有权限分级（只读 / 每次确认 / 全自动）。使用原则：

- **陌生项目/大改动**：让每条写命令都过你眼前——慢，但看得见
- **熟悉的例行任务**（跑测试、格式化）：放行执行类命令
- **删除类、网络发布类、git push**：永远人工确认
- 危险操作哪怕全自动模式也应让 AI **先说明再执行**（"我准备 rm data/ 下 X，因为 Y"）

## 4. 与 git 配合：让每一步都可回滚

代理 + git 是天作之合，标准姿势：

```
干净工作区 → 让 AI 做一个逻辑任务 → review diff → 提交（一个任务一个 commit）
→ 下一个任务 → …
```

- **永远不要在未提交的大改动上再叠新任务**——出错时无法定位是哪一步引入的
- AI 的 commit message 质量不错，但**你要读**：它会如实描述"做了什么"，包括它自作主张做的部分
- 出问题就 `git revert` / `git reset`，比让 AI"改回去"可靠一万倍

## 5. 长任务的上下文管理

终端代理连续工作会积累超长对话，触发第一章说的"遗忘"。对策：

- 每完成一个逻辑单元就让其提交 commit，然后**开新会话**继续下一单元
- 新会话开头让代理重新探索相关文件（它能自己读代码，比背着旧对话更准）
- 跨会话要传递的是"决定过什么"，写进记忆文件或任务文档，而不是依赖对话记忆

## 常见误区

1. **一句"帮我把项目优化一下"就去喝咖啡** —— 全权委托 = 大概率大范围重写 + 三处理解偏差
2. **不开测试就让代理改核心逻辑** —— 它会"看起来改好了"，验证闭环缺失
3. **diff 不看直接提交** —— AI 的改动里混着自作主张的部分，只有 diff 能暴露
4. **在脏工作区连续叠加任务** —— 出错无法二分定位

## 小结

- 四步循环：探索→计划→执行→验证，计划必须人工放行
- AGENTS.md 沉淀项目规则和踩坑；权限从紧，删除/发布永不离手
- 一个任务一个 commit；长任务切会话，靠文档而不是靠记忆延续

## 练习

1. 给你正在维护的项目写一份 AGENTS.md（至少含技术栈、验证命令、一条红线）
2. 用四步循环让代理加一个小功能，在"计划"阶段砍掉它方案里你不认可的部分
3. 体验回滚价值：故意批准一个会失败的任务，然后用 git 干净地回到任务前

# AI 编程基础与工具版图

用好 AI 的第一步不是学工具按钮，而是**理解它的工作方式**——知道它怎么"思考"，才能预判它什么时候可靠、什么时候会一本正经地胡说。

## 1. LLM 是怎么工作的？

三个必须理解的概念：

| 概念 | 通俗解释 | 对使用的影响 |
|------|----------|--------------|
| **Token** | 模型处理文本的最小单位（约 0.5-1.5 个汉字/0.75 个英文单词） | 按 token 计费；超长内容会被截断 |
| **上下文窗口** | 模型一次能"看见"的全部内容长度 | 对话太长后它会**忘掉开头**——不是变笨了，是看不见了 |
| **幻觉** | 对不知道的事生成看似合理实则错误的内容 | **会编造不存在的 API、参数、配置项**——必须验证 |

::: warning 最重要的认知
LLM 的本质是"根据上文预测下一个 token"，它**没有事实数据库、没有真伪判断**。它输出 `fs.readFileSycn()` 这种不存在的函数时，语气和输出正确函数时一模一样。把 AI 当作"能力很强但需要复核的新人同事"，而不是"永不出错的权威"。
:::

## 2. AI 编程工具版图

| 类型 | 代表 | 特点 |
|------|------|------|
| **对话式助手** | ChatGPT、Claude、DeepSeek 网页版 | 通用问答，代码需手动复制回项目 |
| **IDE 内嵌补全** | GitHub Copilot、通义灵码、文心快码 | 边写边补全，最轻量 |
| **IDE 智能体** | Cursor、Windsurf | 能读懂项目、直接编辑多文件 |
| **终端代理（CLI Agent）** | Claude Code、Gemini CLI、ZCode | 在命令行里自主探索代码、执行命令、跑测试 |
| **代码审查/专项** | CodeRabbit 等 | 聚焦 PR 审查等单一场景 |

**演进主线**：从"补全一行" → "改一个函数" → "自主完成一个任务"。越往右效率越高，但**人保留最终把关权**的原则不变。

## 3. AI 擅长什么、不擅长什么？

**高置信度交给 AI**（约 80% 以上成功率）：

-样板代码：CRUD、配置文件、正则表达式、单元测试骨架
- 语言/框架迁移：Python→Go、Vue2→Vue3 的机械改写
- 解释与文档：读陌生代码、写注释和 README
- 排障线索：贴报错让它列可能原因清单

**低置信度必须人主导**：

- 架构决策：AI 给的方案往往"教科书正确"但不适配你的业务约束
- 安全敏感：认证、加密、权限——错了就是事故
- 冷门/新版本 API：训练数据滞后，幻觉高发区
- 性能调优：需要真实压测数据，不是猜

## 4. 一个真实例子：幻觉长什么样

> 问：帮我用 Node.js 删掉目录下所有 `.tmp` 文件
>
> AI 答：可以用 `fs.removeTmpFiles(dir)` 这个内置方法……

`fs.removeTmpFiles` **不存在**。正确写法：

```javascript
import { readdirSync, unlinkSync } from 'node:fs';
import { join } from 'node:path';

for (const f of readdirSync(dir)) {
  if (f.endsWith('.tmp')) unlinkSync(join(dir, f));
}
```

**教训**：AI 给的每个 API 名，你不认识就去查官方文档——这一步不能省。

## 常见误区

1. **"AI 说得这么肯定，应该是对的"** ——语气可信度 = 0，幻觉从不心虚
2. **对话无限长地聊** ——超出上下文窗口后它忘了你最初的需求，答案越来越偏；重要任务开新会话并重述关键背景
3. **把 AI 当搜索引擎用** ——查"某库某版本是否支持 X"应该查文档/源码，AI 的版本知识是滞后的

## 小结

- LLM = 按上文预测 token：会忘（上下文窗口）、会编（幻觉）
- 工具四层：对话、补全、IDE 智能体、终端代理——把关责任始终在人
- 样板代码放心交；架构、安全、冷门 API 必须人主导

## 练习

1. 故意问 AI 一个不存在的库的用法，观察它是否会"认真编造"
2. 把你最近写的一段代码交给 AI 解释，对比它的解释和你自己的理解差在哪
3. 记录一次 AI 出错的经历，归因：幻觉 / 上下文丢失 / 需求没说清？

# 简历与作品集

项目做完只是素材，写进简历的是**证据**。本章解决：项目怎么写才有说服力、AI 技能怎么写才是加分、作品集怎么经营门面。

## 1. 项目写进简历：量化 + 决策感

❌ 减分写法（AI 项目的典型反面）：

```text
· 使用 AI 开发了一个书签管理系统，功能完善，界面美观
· 熟练使用 Claude、Cursor、Copilot 等多种 AI 工具
```

空洞、无证据、无法追问。

✅ 加分写法（每条 = 动作 + 技术 + 可验证结果）：

```text
· 独立设计并交付本地书签管理 CLI（Node.js/SQLite）：定义需求与
  架构，AI 辅助实现，两周完成 MVP；含 21 项自检护栏，npm test 全绿
· 建立可复用的 AI 结对工作流（需求评审→计划审批→小步提交→
  测试护栏），AI 辅助开发返工率显著低于纯手工迭代
· 输出架构决策记录 5 篇，覆盖存储选型、错误处理策略等关键取舍
```

**公式**：`做了什么（动词开头）+ 怎么做的（技术/方法）+ 结果（数字或可验证状态）`。数字不必惊人——"21 项自检""两周 MVP""5 篇 ADR"这种小而真的数字，比"提升 300% 效率"可信十倍。

## 2. AI 技能怎么写

**没用的写法**：技能栏罗列 "ChatGPT / Claude / Cursor / Copilot"——会打字的人都会这么写。

**有用的写法**：把 AI 写成**工作流能力**：

```text
✅ AI 协作开发：掌握提示词工程与终端代理工作流（探索-计划-
   执行-验证），具备 AI 代码安全审查能力（命令注入/SQL注入/
   路径穿越检查清单），自建测试护栏保障 AI 产出质量
```

面试官要的不是"用过"，是**"用得比别人好，而且知道风险在哪"**——这正好是你第 2、3、5 章学过的内容，直接翻译成简历语言。

## 3. GitHub 作品集门面

面试官真的会点开你的 GitHub，四件事决定第一印象：

| 检查项 | 标准 | 常见失分 |
|--------|------|----------|
| **Pinned 置顶** | 3-4 个最想被看的仓库 | 默认按星级摆了一堆课程作业 |
| **仓库 README** | 置顶仓必须完整（上一章模板） | 空README / 一行"my project" |
| **提交历史** | 持续、粒度合理的小步提交 | 一天 40 个同格式提交（脚本感）或一次性巨石提交 |
| **仓库卫生** | 无 .env、无 node_modules、有 .gitignore | 密钥提交进历史 = 直接出局 |

**绿墙（贡献图）不是刷出来的**：真实做项目 2-6 周，自然会有一段密集区 + 断续维护——这个形状就是真实的形状，别修饰。

## 4. 诚实边界（红线）

1. **不写没用过的**：每一行简历都会被追问；写了 "K8s" 就会被问 K8s，答不上比不写减分十倍
2. **AI 项目必须能答辩**：所有署名的代码，你都要能解释任意一行在干什么。做不到的部分，回去搞懂再写上去
3. **不编造数据**："服务 200 人使用" 一追问"怎么部署的、日志在哪"就塌；个人项目写个人项目的真实规模
4. **作品集不搬运**：fork 别人的项目摆在置顶 = 负资产

## 5. 一页纸项目档案（面试前速查）

给每个简历项目做一张卡片，面试当天扫一眼即可上膛：

```markdown
# 项目：书签管理 CLI（2026.10）
一句话：本地 SQLite 书签管理，解决浏览器书签不能打标签的问题
技术栈：Node.js 20 / better-sqlite3 / commander
我做的：需求定义、架构设计、验收标准；AI 辅助实现（七成），全量 review
量化：2 周 MVP / 21 项自检 / 5 篇 ADR / npm test 全绿
最难的坑：SQLite WAL 备份一致性 → 检查点后快照方案
可以深挖：ADR-001 存储选型；错误提示设计；为什么不做 GUI（非目标）
仓库：github.com/xxx/bm
```

## 常见误区

1. **简历堆形容词**——"完善、美观、强大"都是不可验证的词，全部换成数字和状态
2. **把 AI 从简历里藏掉**——2026 年的岗位默认你会用 AI；藏 = 显得不会用或不敢用，写方法论 = 差异化
3. **GitHub 空着就投**——简历写了仓库链接，面试官 100% 会点；点了比没链接更糟

## 小结

- 项目条目公式：动作 + 技术 + 可验证结果；小而真的数字 > 大而空的百分比
- AI 写成工作流能力，不是工具清单
- GitHub 四查：置顶、README、提交形状、卫生；密钥进历史 = 出局
- 一页纸项目档案：面试当天你的"外挂内存"

## 练习

1. 按公式重写你项目的 3 条简历条目，删光所有形容词
2. 整理 GitHub：置顶、README、扫一遍历史里的敏感信息
3. 给每个简历项目做一页纸档案，找人模拟追问十分钟

# 交付打磨

面试官平均只给一个开源项目 **3 分钟**：30 秒读 README，1 分钟 clone 试跑，90 秒决定要不要深挖。本章把"能跑的项目"打磨成"能通过答辩的项目"。

## 1. 先知道面试官怎么看你的项目

```
第 1 眼  README 首屏   → 这是什么、跟我岗位有关系吗、跑得起来吗
第 2 眼  git 历史      → 真的是你做的吗（提交粒度、时间跨度、信息质量）
第 3 眼  代码结构      → 命名、分层、有没有测试
第 4 刀  深挖提问      → 为什么这么设计？最难的坑？重做会改什么？
```

**git 历史是被低估的面试资产**：跟着本课程第四章"一个任务一个 commit"做下来的仓库，历史本身就是证据链——每个提交信息清晰、粒度合理、时间跨度真实。反过来，一个"Initial commit 包含全部代码"的仓库，AI 代写的嫌疑洗不掉。

## 2. README：项目的简历

直接可套的模板：

```markdown
# 项目名 —— 一句话定位

> 给 [谁] 解决 [什么问题]。替代 [什么旧做法]。

## ✨ 演示
（一张 GIF 或 10 行终端输出，比一千字描述都直观）

## 🚀 快速开始
git clone ... && cd xxx
npm install && npm test        # 先证明健康
npm start                       # 一条命令跑起来

## 🧭 它是怎么工作的
（一张架构图/数据流图 + 五行文字说明核心链路）

## 🔍 技术决策
- 为什么选 SQLite 而不是 MySQL → 见 docs/adr.md
- 为什么自研解析而不用 X 库 → 见 docs/adr.md

## ⚠️ 已知限制
（诚实列出 2-3 条：不支持什么、什么场景会慢）

## 🤖 AI 使用说明
本项目采用 AI 结对开发：需求与设计人工主导，实现由 AI 辅助，
全部代码经人工 review，npm test 护栏验证。
```

三个要点：**演示先于文档**（先让人看到它活着）；**限制要诚实**（面试官对"知道边界"的印象分远高于"号称完美"）；**AI 使用说明是加分项**——它展示的是你的工作流素养，而非减分项。

## 3. 架构决策记录（ADR，简版）

每个"为什么选 X 不选 Y"写一张卡片，存 `docs/adr.md`：

```markdown
## ADR-001：数据存储选 SQLite 而非 MySQL
背景：单机单用户场景，期望零配置分发
选择：SQLite（better-sqlite3，WAL 模式）
代价：不支持多进程写、并发上限低
否决项：MySQL（部署重）、纯 JSON（无查询能力）
日期：2026-10
```

答辩时 90% 的深挖题，答案已经在你的 ADR 里——**临场回忆不如提前落笔**。3-5 张 ADR 就够，多了是负担。

## 4. 深挖防线：面试官的六连问预演

| 必问题 | 你的准备 |
|--------|----------|
| 为什么这么设计？ | ADR 卡片，脱口而出 |
| 最难的一个坑？ | 从踩坑清单挑一个"发现→定位→修复→预防"闭环的 |
| 哪部分是 AI 写的？ | 诚实+方法论："实现约七成 AI 辅助，架构与验收标准是我定的，看这个 git 历史" |
| 为什么不用现成的 X？ | 说明你调研过 X（一分钟即可），给出匹配度理由 |
| 如果用户量 ×100？ | 提前想好瓶颈点在哪、怎么扩（说思路即可，别吹重写方案） |
| 重做一遍会改什么？ | 真诚说 1-2 条（有反思的人可信） |

**"哪部分是 AI 写的"是送分题不是送命题**：回避和撒谎都会连锁崩塌（下一问就是代码细节）；坦然 + 方法论 + 证据链，反而变成全场高光。

## 5. 打磨清单（按性价比排序）

1. **一键启动**：陌生环境按 README ≤10 分钟跑通（找个朋友实测，别自己想当然）
2. **演示数据**：预置一份能立即看到效果的数据；空白系统的第一印象 = 没做完
3. **错误路径**：故意输错命令，提示是否友好——面试官一定会试
4. **npm test 全绿**：把测试命令放进 README 首屏
5. **一张架构图**：手画拍照也行，有图胜过千言
6. **删掉死代码和调试残留**：注释掉的大段代码 = 减分项
7. **commit 信息回扫**：最后过一遍历史，重要提交是否说清了"为什么"

## 常见误区

1. **功能不够多不敢投** —— 面试官不看功能清单长度；三个功能打磨到位 > 十个功能半成品
2. **README 写成技术散文** —— 没人有空读；演示、快速开始、决策，三段足矣
3. **把 AI 痕迹藏起来** —— 藏不住（一问便知），坦白的.workflows 反而是差异化亮点
4. **没有"已知限制"** —— 面试官会替你找出来；自己先说，主动权在你

## 小结

- 面试官 3 分钟定生死：README 首屏、git 证据链、一键可跑
- ADR 提前落笔，六连问全部有稿；"AI 写的"坦然答 + 方法论 + 证据链
- 打磨性价比：一键启动 > 演示数据 > 错误路径 > 全绿测试

## 练习

1. 按模板重写你项目的 README，找一位朋友实测"10 分钟跑起来"
2. 写 3 张 ADR，覆盖你项目里最纠结的三个选择
3. 对着六连问自问自答回录音，听三遍，改到流畅

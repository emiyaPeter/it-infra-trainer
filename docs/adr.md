# 架构决策记录（ADR）

> 每个重要取舍一张卡片：背景 → 选择 → 代价 → 否决项。答辩深挖题的答案都在这里。

## ADR-001：默认启动只保留单进程，认证服务降级为可选组件（v2.2）

**背景**：v2.1 引入 Express 认证服务（3456 端口），但 Web 前端随后演进为纯 localStorage 方案，服务端的注册/登录接口已无任何调用方——一个每次启动都拉起的僵尸进程。

**选择**：认证服务退出默认启动路径（`npm run auth` 保留手动入口），启动器只起 VitePress。

**代价**：SQLite 侧与浏览器侧形成两个独立数据域，不互相同步。

**否决项**：让 Web 重新接回服务端（破坏"纯静态断网可用"的核心承诺）；彻底删除代码（保留排查 v2.1 历史数据的入口，观察期后再删）。

**深挖点**：为什么"静态可用"优先于"数据统一"——目标用户是零基础自学者，部署门槛的杀伤力大于数据同步的价值；数据迁移用导出/导入 JSON 解决（ADR-006）。

## ADR-002：Web 账户存 localStorage，密码用 2000 轮迭代哈希（v2.2）

**背景**：Web 端无后端，账户只能存浏览器。

**选择**：`v2$轮数$哈希` 格式，SHA-256 迭代 2000 轮 + 按用户加盐；优先 Web Crypto API，非安全上下文（局域网 IP 访问）降级纯 JS 实现；旧单轮哈希登录时透明升级。

**代价**：纯 JS 降级路径登录耗时约百毫秒级；安全性仍弱于服务端 bcrypt（无 Pepper、可离线撞库）——以"单机个人设备"威胁模型接受。

**否决项**：bcrypt（需要后端）；纯 PBKDF2（非安全上下文无原生实现，纯 JS 实现过重）。

**深挖点**：`crypto.subtle` 只在安全上下文可用——localhost 算、局域网 IP 不算，这是很多人不知道的边界。

## ADR-003：实操检查统一经 WSL 执行（v2.2）

**背景**：实验/作业的自动检查原硬编码 `/bin/bash`，在 Windows 宿主上**全部静默失败**；文件类检查用宿主 fs 找 `/home/user` 路径同样必然失败。

**选择**：新增 `utils/bash.js`，Windows 上经 `wsl.exe -e bash -c` 执行，用 **execFileSync 参数数组**传命令；文件检查改为 bash 内判定（test/grep）；探测 WSL 缺失时返回安装引导而非假失败。

**代价**：每次检查有 WSL 调用开销（缓存探测结果缓解）；路径赋值不加引号（依赖实验路径无空格的约定）。

**否决项**：execSync + shell 拼接（cmd.exe 引号转义不可靠，经典的注入与断裂问题）；UNC 路径 `\\wsl$\...` 访问 WSL 文件系统（发行版名不可枚举、性能差）。

**深挖点**：为什么不引号——bash 赋值语境的波浪号展开要求不加引号，取舍后用"受控内容"兜底。

## ADR-004：启动器批处理使用 GBK 编码（v2.2）

**背景**：原 bat 为 UTF-8 + `chcp 65001`。cmd 解析批处理按当前代码页逐块读字节，**执行中途切换代码页会导致解析器字节错位**，后续中文行读乱、语法中止、窗口闪退——用户环境必现，我的测试环境因 PATH 缺 chcp 反而侥幸通过（测试环境差异的经典教训）。

**选择**：GBK 编码（中文 Windows 控制台原生编码）+ 移除 chcp 与 emoji，从根上消除切换可能。

**代价**：非中文系统上 bat 显示乱码（功能不受影响，解析仍正确）。

**否决项**：UTF-8 + BOM + chcp 提前（仍存在切换时机的解析错位风险，属于"通常没问题"而非"必然没问题"）。

**深挖点**：为什么测试没拦住——见 [复盘第 1 节](./retrospective.md#坑1启动器在用户机器上闪退)。

## ADR-005：数据库备份先做 WAL 检查点（v2.2）

**背景**：SQLite WAL 模式下，最近写入可能还在 -wal 文件里，直接复制主库文件会得到**缺尾部数据的快照**。

**选择**：备份流程：打开连接 → `PRAGMA wal_checkpoint(TRUNCATE)` → 关闭 → 复制主文件 → 轮转保留 7 份。

**代价**：备份瞬间有写入停顿（个人场景毫秒级，可忽略）。

**否决项**：直接 copyFile（快照可能不一致）；依赖 VACUUM INTO（同样有效但重写全库，代价更高——两者皆可，选了更轻的）。

## ADR-006：双数据域用"导出/导入 JSON"桥接（v2.2）

**背景**：ADR-001 造就了浏览器（localStorage）与 CLI（SQLite）两个数据域，用户换浏览器/换电脑会丢进度。

**选择**：Web 仪表盘导出/导入备份（账户+按用户进度，按姓名合并、进度覆盖、确认弹窗）；CLI 侧 `export-progress` 导出数据库记录。

**代价**：手动两步迁移，无自动同步（无冲突问题的补偿收益）。

**否决项**：定时双向同步（个人离线场景过度设计，且引入冲突解决复杂度）。

## ADR-008：AI 答疑仅限本地 CLI，Web 端不接入（v2.4）

**背景**：v2.4 引入 AI 答疑（`ask` 命令，OpenAI 兼容协议，默认 DeepSeek）。设计时的核心约束是**密钥保密**：站点以纯静态形式部署在公网（GitHub Pages），任何进入前端代码的密钥都会公开泄露。

**选择**：AI 调用只在本地 CLI 进程中发生；密钥经 `npm run set-key` 交互式写入 `.env`（gitignored，支持 DeepSeek/Kimi/智谱/自定义，重复运行即更换）；回答采用 RAG-lite——先检索本地课程内容作为上下文，回答附课程出处。

**代价**：网页端没有 AI 入口（对纯浏览器用户不可见）；CLI 调用需要本机联网到所选服务商。

**否决项**：Web 前端直连 API（密钥必泄露）；本地起 AI 代理服务供网页调用（破坏单进程/零后端架构，且公网站点依旧用不上）。

**深挖点**：密钥边界 = 部署形态边界——纯静态公网站的智能功能必须接受"无密钥"现实，把 AI 放回用户自己的机器上是唯一既保密又可用的位置。

**修订（v2.5）**：边界从"Web 端不接 AI"细化为"**站点零密钥 + BYOK**"。随堂测验的错题精讲与填空题 AI 判分需要网页端智能，采用 BYOK（Bring Your Own Key）模式：密钥由访客在浏览器里自行填写，存于本机 localStorage（`it-trainer-ai-config`），请求由访客浏览器直连所选服务商——**站点代码与仓库仍然零密钥**，原决策的保密逻辑不变；否决项（站点内置密钥）依旧否决。附带约束：BYOK 是可选增强，不配密钥时测验功能完整（填空题按标准答案+可接受写法本地判分）；AI 判错时自动追加一轮**对抗审计**，专门防止"把对的判错"。

## ADR-009：完成机制双轨制——阅读标记与测验达标并存（v2.5）

**背景**：原完成机制是纯手动的"标记已完成"。用户提出质疑：自报完成无法证明掌握，应由测验效果驱动。但题库是模块级（5 套题）而章节是 78 个——17 个模块中 12 个暂无题库，纯测验驱动会让无题模块永远无法完成，且"读完了"这一阅读轨迹信号本身有价值。

**选择**：双轨并存、同一存储。轨道一：章节页手动「标记已完成」（阅读轨迹）；轨道二：模块测验 ≥80 分时自动批量点亮该模块全部章节（`setPageDone` 逐章写入，来源为构建时从 `courses/**/*.md` glob 推导的章节清单，零手工维护）并记入 `verifiedModules`。仪表盘增加"测验达标模块"展示。

**代价**：两条路径写同一份进度，无法区分某章是"读完的"还是"测过的"；`verifiedModules` 只覆盖有题库的模块。

**否决项**：纯测验驱动（无题库模块瘫痪，进度大面积停摆）；测验通过才解锁标记按钮（把两种信号强行串行，徒增摩擦）。

**深挖点**：完成机制的本质是"证据等级"——阅读是弱证据，测验是强证据；强证据可以覆盖弱证据（测过视为读过的超集），反向不成立，这正是双轨合并的安全方向。

## ADR-010：主观题 AI 判卷——三档计分、错杀审计与"无密钥不惩罚"（v2.6）

**背景**：题库扩容后引入问答题（short-answer）与实操题（coding），此类题目无法本地规则判分。同时站点是纯静态部署，没有后端判卷服务；BYOK（ADR-008 修订版）是 Web 端唯一的 AI 通道，而密钥是可选项。

**选择**：分层判卷 + 无密钥降级自评。① 有密钥：AI 按三档判分（correct=1 分 / partial=0.5 分 / incorrect=0 分），temperature 0 + 结构化 JSON；**仅 incorrect 触发对抗审计**（寻找应得部分分/全分的依据，可改判），与填空题的审计哲学一致——第二发子弹只打"错杀"。② 无密钥或 AI 不可用：题目照常可做，作答后解锁参考答案**自评**（答对移出错题本/答错记入），主观题**剔除出总分**，客观题照常计分与达标。③ 部分得分（partial）不进错题本——接近掌握不算"错"，只在结果页提示巩固。④ CLI 遇主观题跳过不计分并给出参考答案（CLI 不接 AI 判卷，保持轻）。

**代价**：无密钥与有密钥的用户分数分母不同（前者不含主观题），跨用户不可直接比较；AI 判卷有延迟（单题 2 次调用上限）。

**否决项**：无密钥时禁止作答主观题（惩罚无密钥用户，违背 BYOK 可选原则）；partial 也进错题本（错题本语义被稀释）；CLI 也接 AI 判卷（CLI 的 .env 与 Web BYOK 两套密钥源叠加复杂度，收益低）。

**深挖点**：**"无密钥不惩罚"原则**——可选增强（AI）的缺失只能少功能，不能降体验：客观题照判、达标照算、错题本照记，主观题退化为"看参考答案自评"的练习。这条原则让 BYOK 从"付费墙"变成"增益器"，是静态站做 AI 功能的伦理边界。

## ADR-011：无后端架构下的账户安全——恢复码即"本机钥匙"的备份（v2.7）

**背景**：账户体系是纯 localStorage（ADR 系列的一贯架构：零后端、静态部署）。密码哈希存本机，没有服务端就没有"手机验证码找回"通道——用户忘记密码 = 学习记录永久锁死。同时用户提出衍生问题：被安排学习者可以随手点"标记已完成"刷课。

**选择**：恢复码方案。注册成功即生成 16 位高熵恢复码（`crypto.getRandomValues`，去易混字符表，≈80 bit 熵），**只存 SHA-256 哈希**（高熵输入单轮哈希即可，无需像密码那样多轮迭代）；明文仅注册后展示一次，已登录用户可在仪表盘重新生成（旧码立即失效）。忘记密码：姓名 + 恢复码 + 新密码重置（同名多账户天然由恢复码消歧）。备份文件纳入恢复码哈希与测验数据（v2 格式）。对刷课问题的回应不是堵按钮而是**学习报告的证据分级呈现**（✅测验达标验证 / 📖仅自报已读 / ⬇未开始），自报数据在报告里一眼可辨。

**代价**：恢复码丢失且密码遗忘时仍无法找回（诚实边界）；纯前端环境下恢复码本身也存本机，防的是"忘密码"不防"清缓存"（后者靠备份提醒缓解）。

**否决项**：邮件/短信找回（需要后端与外部服务，破坏零后端架构）；把恢复码明文存 localStorage 方便随时查看（任何能读本机存储的脚本都能拿走钥匙，哈希存储至少把泄漏面限制在"展示的那一次"）；标记完成加防作弊门槛（挂机即可绕过，伤真实用户，见复盘坑 7 的教训——用呈现层区分证据等级替代不可靠的拦截）。

**深挖点**：无后端系统的安全设计本质是**威胁建模的诚实**——防"自己忘了"（恢复码）、防"数据没了"（备份+提醒）、防"报告造假给第三方看"（证据分级呈现）各用各的工具；而防"本机被入侵"超出任何纯前端系统能力，明确说不比假装能强。

## ADR-007：Web 进度以"章节完成标记"为最小单元（v2.2）

**背景**：考古发现仪表盘一直读取 `it-trainer-progress-*` 数据，但全代码库**没有任何写入者**——进度条从未真实工作过。

**选择**：课程页右下角浮动标记按钮（正则识别两位数字章节页）写入按用户隔离的进度；仪表盘按"已完成章节/模块目录常量"计算百分比。

**代价**：模块章节总数是手工维护的常量（AGENTS.md 里有更新提醒）。

**否决项**：构建时自动统计（值得做，见复盘"遗留改进"）；按浏览行为自动计进度（无法区分走马观花）。
